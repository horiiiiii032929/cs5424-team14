\needspace{4\baselineskip}\section{Task 3: Baseline design for Workload B}
Workload B is made up of the same 9 transactions but with a different weight mix. Most notably, 80\% of the transactions involve writing data (T1, T2, T5, T7, T8, T9). T7 itself occupies the largest proportion at 30\%, 3 times higher than the next most frequent transaction.\par
Evidence review  --  22 October: b0-b6 scripts and raw outputs are archived from branch commit 5fa38157a7c1cb9abf1097e731f934a97a3db7c4. All 42 cases have been checked for phase exits and transaction-log counts. Every 64-client B case has an aborted warmup or measurement; those values below are diagnostic observations, excluded from clean performance comparisons. Node allocations vary; no matched full-series speedup is established.\par

\needspace{4\baselineskip}\subsection*{Experiment setup}
Every benchmark experiment runs as a single Slurm job on NUS SoC compute cluster. The job deploys a 5-node Citus PostgreSQL distributed database, with a single coordinator and 4 workers. \texttt{pgbench} runs on the coordinator node and connects only to the coordinator, such that every statement passes through it.\par
\begin{itemize}
\item The software versions are Citus \texttt{14.1.0} on PostgreSQL \texttt{18.6}.
\end{itemize}
The default settings used for the benchmarking are:\par
\begin{itemize}
\item \texttt{shared\_\allowbreak{}buffers} 1 GB
\item \texttt{work\_\allowbreak{}mem} 32 MB
\item \texttt{max\_\allowbreak{}connections} 1000,
\item \texttt{SERIALIZABLE} isolation
\item repartition joins enabled
\item \texttt{citus.max\_\allowbreak{}adaptive\_\allowbreak{}executor\_\allowbreak{}pool\_\allowbreak{}size} 4
\item \texttt{citus.max\_\allowbreak{}shared\_\allowbreak{}pool\_\allowbreak{}size} 300
\end{itemize}
